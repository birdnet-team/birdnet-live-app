# 업로드

업로드는 완료된 Session을 여러 휴대전화에서 하나의 프로젝트 폴더로 보냅니다. 프로젝트 책임자가 폴더를 한 번 설정하고 링크나 QR 코드를 배포하면, 참여자는 각자 그것을 붙여 넣거나 스캔하고, 그 뒤로는 어떤 Session이든 공유 대화상자에서 두 번만 눌러 그 폴더로 보낼 수 있습니다. ARU 운용은 완료된 모든 Session을 스스로 보낼 수 있습니다.

업로드는 한 방향으로만 진행됩니다. 앱은 프로젝트 폴더에 파일을 쓰기만 하고, 그곳의 내용을 읽거나 목록을 보거나 삭제하는 일은 절대 없습니다. 휴대전화에서 Session을 삭제해도 업로드된 복사본은 그대로 남으며, 대상을 체크하거나 ARU 자동 업로드를 켜지 않는 한 아무것도 업로드되지 않습니다.

## 작동 방식

**대상**은 앱이 쓸 수 있는 WebDAV 폴더입니다. 세 가지 종류를 별도 설정 없이 바로 사용할 수 있습니다:

- **Nextcloud File Drop** 공유. 대부분의 프로젝트에 권장되는 선택입니다.
- 사용자 이름과 비밀번호가 있는 임의의 **WebDAV 주소**. 예를 들어 자신의 클라우드 계정에 있는 폴더나 기관 서버입니다.
- BirdNET Live와 함께 제공되는 **참조 드롭 서버**. 참여자별 토큰과 미리 준비된 CSV 내보내기를 원하는 책임자를 위한 것입니다([Developer Guide](../developer/upload-drop-server.md) 참고).

모든 업로드는 **Session당 ZIP 파일 하나**이며, 공유 내보내기와 같은 방식으로 이름이 붙습니다. 예를 들어 `BirdNET_Live_2026-05-14_06-30-00_#13.zip`과 같습니다. 여기에는 항상 Session의 JSON 기록이 들어가고, 체크한 항목에 따라 오디오, 감지 테이블, HTML 보고서, 앱 메타데이터 파일이 들어갑니다. ZIP은 **업로드 ID**로 이름 붙은 폴더에 저장됩니다. 업로드 ID는 앱이 이 설치용으로 보관하는 무작위 식별자에서 유도한 8자리 코드입니다. 따라서 프로젝트 책임자의 폴더는 다음과 같은 모습입니다:

```
4ee91c8f/BirdNET_Live_2026-05-14_06-30-00_#13.zip
4ee91c8f/BirdNET_Live_2026-05-14_07-02-10_#14.zip
b27c0e51/BirdNET_Live_2026-05-14_06-45-00_#3.zip
.birdnet-live/4ee91c8f.json
.birdnet-live/b27c0e51.json
```

`.birdnet-live` 폴더에는 연결 테스트가 기록한 기기별 작은 등록 파일이 하나씩 들어 있습니다. Nextcloud는 "숨김 파일 표시"가 켜져 있지 않으면 이 폴더를 숨깁니다. 이 파일에는 업로드 ID, 앱 버전, 플랫폼, 그리고 참여자가 입력한 선택 사항인 **참여자 식별자**(이름, 이메일 또는 참여자 번호)가 담겨 있어, 책임자는 어떤 이름도 폴더 이름이 되는 일 없이 각 코드 뒤에 누가 있는지 알 수 있습니다. 같은 식별자는 업로드된 모든 Session의 JSON 기록에도 기록됩니다.

## 프로젝트 책임자용

### 옵션 A: Nextcloud File Drop

1. Nextcloud에서 프로젝트용 폴더를 만듭니다. 예를 들어 `Spring Survey 2027`입니다.
2. 폴더의 공유 패널을 열고 **공유 링크**를 만든 뒤, 권한을 **File drop(업로드 전용)**으로 설정합니다. 그러면 참여자는 파일을 추가할 수는 있지만 다른 사람이 보낸 내용은 절대 볼 수 없습니다.
3. 링크에 **비밀번호**를 설정합니다. 비밀번호가 없으면 링크를 발견한 누구나 폴더에 업로드할 수 있습니다. 그래도 File Drop은 읽을 수 없으므로, 비밀번호가 없는 것은 앱이 아무 경고 없이 받아들이는 선택입니다.
4. 필요하면 프로젝트 종료 시점으로 만료일을 설정합니다.
5. 공유 링크를 복사합니다. `https://cloud.example.org/s/AbCdEf123456`과 같은 형태입니다.

앱이 그 링크를 공유의 WebDAV 엔드포인트로 직접 변환하므로 참여자는 WebDAV 주소를 볼 일이 없습니다. File Drop은 절대 덮어쓰지 않습니다. 참여자가 같은 Session을 다시 업로드하면 Nextcloud는 이전 복사본을 번호가 붙은 이름으로 보관하므로, 번호가 없는 파일이 최신 파일입니다.

**업로드 및 편집** 권한의 Nextcloud 공유도 작동하지만, 링크가 있는 누구나 다른 모든 사람의 데이터를 읽을 수 있게 되므로 앱은 자격 증명으로 폴더 목록을 볼 수 있다고 참여자에게 경고합니다. 읽기 전용 공유는 연결 테스트에서 거부됩니다.

### 옵션 B: 자신의 WebDAV 폴더

어떤 WebDAV 서버든 사용할 수 있습니다. 개인 클라우드 계정의 폴더, 기관 파일 서버, ownCloud, 또는 일반 계정을 사용하는 Nextcloud가 그 예입니다. 참여자는 참여할 때 **고급**에서 주소와 함께 사용자 이름과 비밀번호를 입력합니다. Nextcloud나 ownCloud 계정에는 로그인 비밀번호가 아니라 계정 보안 설정에서 발급한 **앱 비밀번호**를 사용하세요. 호스트 이름만 입력하면 앱은 그 호스트의 일반적인 Nextcloud 및 ownCloud 위치도 시도합니다.

이런 자격 증명은 대개 폴더를 읽을 수 있으므로 연결 테스트에 경고가 표시됩니다. 참여자가 모두 한 팀이 아니라면 쓰기 전용 설정을 사용하는 것이 좋습니다.

### 옵션 C: 참조 드롭 서버

소스 저장소의 `tools/webdav_drop_server`는 작은 Python 서버로, 취소할 수 있는 참여자별 토큰, 업로드된 모든 JSON 기록을 `sessions.csv`, `detections.csv`, `species_summary.csv`로 병합하는 `collect` 명령, 그리고 참여 링크와 QR 코드를 출력하는 `invite` 명령을 제공합니다. 설치와 배포는 [Developer Guide](../developer/upload-drop-server.md)에 설명되어 있습니다.

### 참여 링크와 QR 코드 만들기

참여 링크는 참여자에게 필요한 모든 것을 하나로 담고 있습니다: 대상, 자격 증명, 프로젝트 이름, 그리고 책임자가 제안하는 기본값입니다. 이 사이트의 [참여 페이지](../join.md)를 열고 다음을 입력합니다:

- **Share link or WebDAV address**: 위에서 만든 Nextcloud 공유 링크 또는 WebDAV 폴더 주소입니다.
- **User name**: Nextcloud 공유 링크라면 비워 둡니다.
- **Share password or token**: 공유 비밀번호, 또는 계정이나 토큰의 비밀 값입니다.
- **Project name shown in the app**: 참여자가 대상 이름으로 보게 될 이름입니다. 참여자가 바꿀 수 있지만 이것이 기본값입니다.
- **Suggest including audio**와 **Suggest Wi-Fi only**: 대상 스위치의 기본값입니다.

**Build link and QR code**를 누릅니다. 모든 처리는 브라우저 안에서 이루어지며 어디로도 전송되지 않습니다. 비밀 값은 링크의 `#` 뒤 부분에 들어 있는데, 브라우저는 이 부분을 페이지를 호스팅하는 웹 서버에 절대 전송하지 않습니다.

또는 먼저 자신의 휴대전화에서 대상에 참여한 뒤(아래 참고), **설정 → 내보내기 및 동기화 → 업로드 대상**에서 그 대상을 열고 **참여 코드 표시**를 누릅니다. 앱은 같은 종류의 QR 코드를 **링크 복사** 버튼과 함께 표시합니다.

### 배포하기

QR 코드를 현장 조사표에 인쇄하거나, 브리핑 때 화면에 띄우거나, 링크를 메시지로 보냅니다. **링크와 코드를 비밀번호처럼 다루세요**: 이를 가진 누구나 프로젝트에 업로드할 수 있습니다. 유출되면 공유 비밀번호를 바꾸거나 토큰을 취소하고 새 코드를 배포합니다.

참여자가 휴대전화 카메라로 코드를 스캔하면 브라우저에 **Open in BirdNET Live** 버튼이 있는 작은 랜딩 페이지가 열리고, 이를 누르면 링크가 입력된 상태로 앱의 대상 추가 화면으로 이동합니다. 링크를 그 화면에 직접 붙여 넣어도 똑같이 작동합니다.

### 책임자에게 보이는 것

기기당 폴더 하나, Session당 ZIP 하나, 그리고 숨겨진 `.birdnet-live` 등록 파일입니다. ZIP을 열면 JSON 기록(항상 포함)과 참여자가 포함하기로 선택한 테이블, 보고서, 오디오가 있습니다. 어떤 업로드 ID 뒤에 어떤 사람이 있는지 알려면 그 코드의 등록 파일을 읽거나, 해당 JSON 기록 중 하나에서 `meta.participant` 필드를 확인합니다. 참조 드롭 서버에서는 `collect`가 이 작업을 대신하여 `participant` 열을 기록합니다.

## 참여자용

### 대상에 참여하기

1. **설정 → 내보내기 및 동기화 → 업로드 대상**을 열고 **대상 추가**를 누릅니다. 카메라로 프로젝트의 QR 코드를 스캔하거나 받은 참여 링크를 누르면 링크가 이미 입력된 같은 화면으로 이동합니다.
2. 참여 링크, Nextcloud 공유 링크 또는 WebDAV 주소를 **참여 링크 또는 서버 주소**에 붙여 넣습니다. **붙여넣기** 버튼은 클립보드에서 가져옵니다.
3. 필요하면 **참여자 ID, 이름 또는 이메일(선택)**을 입력합니다. 이 값은 모든 업로드와 함께 저장되어 프로젝트 책임자가 보낸 사람을 알 수 있으며, 폴더 이름에는 절대 나타나지 않습니다. 입력란 아래에 앱은 업로드가 저장될 폴더인 **내 업로드 ID**를 표시합니다.
4. 일반 WebDAV 주소라면 **고급**을 열고 **사용자 이름**과 **비밀번호 또는 토큰**을 입력합니다. Nextcloud 공유 링크에는 둘 다 필요 없습니다. 공유에 비밀번호가 있으면 그것을 비밀번호로 입력합니다.
5. **연결 테스트**를 누릅니다. 앱은 서버에 접속해 숨김 등록 폴더를 만들고, 자격 증명으로 폴더 목록을 볼 수 있는지 확인하고, 등록 파일을 기록합니다. 결과는 한 문장으로 표시됩니다: **연결이 정상입니다**, 읽어 두어야 할 경고, 또는 가능한 해결 방법이 함께 표시되는 실패입니다.
6. 대상에 **대상 이름**(참여 링크에서 미리 입력됨)을 지정하고, **Wi-Fi에서만 업로드**할지 결정한 뒤 **대상 저장**을 누릅니다.

테스트를 통과하기 전에는 아무것도 저장되지 않습니다. 자격 증명은 기기 키체인에 들어가며 내보낸 데이터에는 절대 포함되지 않습니다.

알아 두어야 할 경고:

- **이 자격 증명으로 대상의 목록을 볼 수 있어 다른 참여자의 데이터를 읽을 수도 있습니다. File Drop 공유나 쓰기 전용 토큰을 사용하는 것이 좋습니다.**는 공유나 계정이 다른 참여자의 데이터를 읽을 수 있다는 뜻입니다. 업로드는 작동하지만, 프로젝트에 팀 밖의 사람이 참여한다면 책임자에게 File Drop이나 쓰기 전용 토큰을 요청하세요.
- **이 공유에는 비밀번호가 없고 목록을 볼 수 있어, 링크가 있는 누구나 다른 참여자의 데이터를 읽을 수 있습니다. 프로젝트 책임자에게 비밀번호를 설정하거나 File Drop을 사용하도록 요청합니다.**는 두 위험이 합쳐진 것입니다: 링크가 있는 누구나 모든 것을 읽을 수 있습니다. 책임자에게 비밀번호를 설정하거나 File Drop을 사용하도록 요청하세요.
- **이 서버는 폴더 생성을 허용하지 않아 업로드에 평면 파일 이름을 사용합니다.**는 참고용 안내입니다: 업로드는 폴더 대신 `4ee91c8f__BirdNET_Live_….zip`과 같은 평면 파일 이름을 사용합니다.

### 대상 화면

목록에서 대상을 누르면 서버 주소, 추가한 시점과 마지막 사용 시점, 그리고 다음 컨트롤이 있는 화면이 열립니다:

- **이름 바꾸기**(앱 바의 연필 아이콘)는 앱에 표시되는 이름을 바꿉니다.
- **Wi-Fi에서만 업로드**는 휴대전화가 셀룰러 네트워크에 연결된 동안 업로드를 보류합니다.
- **ARU Sessions 자동 업로드**는 완료된 모든 ARU Session을 확인 없이 이 대상의 대기열에 추가합니다(아래 참고).
- **연결 테스트**는 연결 테스트를 다시 실행합니다. 예를 들어 책임자가 비밀번호를 바꾼 뒤에 사용합니다.
- **참여 코드 표시**는 QR 코드와 **링크 복사**를 표시하여 두 번째 휴대전화가 같은 대상에 참여할 수 있게 합니다.
- **대상 제거**는 대상과 그 자격 증명을 잊고 해당 대상으로의 대기 중인 업로드를 버립니다. 이미 업로드된 Session은 서버에 남습니다.

대상 목록의 첫 항목은 **내 업로드 ID**이며 그 아래에 참여자 식별자가 표시됩니다. 누르면 식별자를 바꿀 수 있습니다. 폴더는 ID로 이름 붙으므로 식별자를 바꿔도 서버의 어떤 것도 이동하지 않습니다.

### Session 업로드하기

업로드는 이미 사용하고 있는 같은 **공유** 동작에서 시작하며, 세 곳에 있습니다:

- Session 목록에서 Session 카드의 **점 세 개 메뉴**(:app-moreVert:);
- Session 목록에서 여러 Session을 선택한 뒤의 **공유** 버튼;
- Session 검토 도구 모음의 **공유** 아이콘(:app-share:).

대상이 하나 이상 있으면 공유 대화상자에 두 개의 탭이 표시됩니다:

- **내용**은 내보내기에 담을 내용을 선택합니다: **오디오**(전체 녹음, 또는 클립만 보관한 경우 감지 클립)와 **메타데이터**(내보내기 및 동기화에서 활성화한 테이블, 보고서, 앱 메타데이터 파일)입니다. 체크 상태는 처음에 설정과 같게 시작하며 이번 공유에만 적용됩니다.
- **보낼 곳**은 **공유 시트**(다른 앱, 파일, 메시지)와 대상별 체크 상자 하나씩을 나열합니다. 탭의 배지는 체크된 대상의 수를 표시합니다. 지난번에 체크한 대상은 미리 체크되어 있지만, 이 Session이 이미 전송된 대상은 예외입니다: 체크되지 않은 상태로 시작하고 날짜와 함께 **업로드됨**과 **다시 업로드하려면 선택합니다**를 표시합니다. 대화상자가 열리면 앱은 각 대상을 조용히 확인합니다. 예를 들어 비밀번호가 바뀌었거나 공유가 제거되어 서버가 업로드를 거부할 것이라고 알리면, 해당 행이 이유와 함께 빨간색으로 바뀝니다.

**공유 시트**의 체크를 해제하면 버튼이 **업로드**로 바뀌고, 둘 다 체크하면 **공유 및 업로드**로 표시됩니다. 스낵바가 대기열에 추가된 Session 수를 확인해 줍니다. Session은 항상 먼저 대기열에 들어간 뒤 백그라운드에서 업로드되므로 계속 작업할 수 있습니다.

### 업로드 진행 확인하기

Session 목록의 Session 카드는 Session 제목 아래 첫 줄에 상태를 표시합니다: **대기 중**, **Wi-Fi 대기 중**, **네트워크 대기 중**, **업로드 중…**, 날짜와 함께 **업로드됨**, 또는 실패입니다. 그 줄을 누르면 **지금 다시 시도**와 **대기열에서 제거**가 있는 대상별 목록이 열립니다. Session 검토는 같은 상태를 앱 바의 구름 아이콘으로 표시하며, 누르면 같은 목록이 열립니다.

실패한 업로드는 점점 긴 간격으로, 최대 6시간 간격까지, 최대 30회까지 스스로 다시 시도합니다. **실패, 다시 시도합니다**는 앱이 다시 시도할 것이라는 뜻입니다. **업로드에 실패했습니다. 대상 설정을 확인합니다.**는 서버가 거부했고 다시 시도해도 소용이 없다는 뜻입니다: 비밀번호가 바뀌었거나, 업로드가 꺼졌거나, 대상이 제거된 경우입니다. 대상을 열어 **연결 테스트**를 실행하고, 자격 증명이 바뀌었다면 대상을 제거한 뒤 다시 추가하세요.

이 줄과 아이콘은 Session이 전송된 대상 중 하나 이상이 설정에 아직 남아 있는 동안에만 표시됩니다. 대상을 제거하면 사라지는데, "업로드됨"이 더 이상 사용자가 가진 어떤 대상에 대한 사실도 아니기 때문입니다.

### 백그라운드에서 실행되는 것

대기 중인 업로드는 앱이 열려 있는 동안과 앱이 포그라운드로 돌아올 때마다 실행됩니다. Android에서는 앱이 닫혀 있어도 실행됩니다. 시스템은 적절한 네트워크(대상이 요구하면 Wi-Fi)가 사용 가능해지면 업로드를 시작하고 대기열이 비워질 때까지 계속 다시 시도합니다. iOS에서는 앱이 열려 있는 동안 업로드가 실행됩니다.

### Session 다시 업로드하기

같은 Session을 다시 업로드하면, 예를 들어 Session 검토에서 감지를 수정한 뒤에는, 같은 폴더에 같은 파일 이름으로 기록됩니다. 이를 허용하는 서버는 파일을 대체하고, Nextcloud File Drop은 대신 이전 복사본을 번호가 붙은 이름으로 보관합니다. 어느 쪽이든 프로젝트 책임자는 최신 버전을 받고 아무것도 삭제되지 않습니다.

## ARU 모드

현장 운용은 많은 Session을 생성하며, 종종 아무도 휴대전화 곁에 없을 때 생성됩니다. 대상에서 **ARU Sessions 자동 업로드**를 켜면, 완료된 모든 ARU Session이 대화상자 없이 오디오와 메타데이터에 대한 내보내기 및 동기화 기본값을 사용하여 그 대상의 대기열에 추가됩니다. 각 주기를 별도의 Session으로 저장하는 운용은 주기별로 업로드하며, 통합된 운용 Session은 두 번 업로드되지 않습니다.

셀룰러 요금제를 사용하는 관측소에서는 요금제가 오디오를 감당할 수 있는 경우가 아니라면 **Wi-Fi에서만 업로드**를 켜 두고, 오디오가 너무 커서 보낼 수 없을 때는 **클립** 또는 **끔**으로 녹음하는 것을 고려하세요. 그러면 업로드는 휴대전화가 적절한 네트워크를 발견할 때마다 흘러 나가며, Android에서는 앱이 백그라운드에 있는 동안에도 진행됩니다.

## 두 가지 실제 예시

### Nextcloud File Drop을 사용하는 주말 Survey

책임자는 대학 Nextcloud에 `Birdathon 2027` 폴더를 만들고, 비밀번호가 있는 File Drop으로 공유하고, 공유 링크와 비밀번호를 참여 페이지에 붙여 넣고, 프로젝트 이름을 지정하고, QR 코드를 브리핑 자료에 인쇄합니다. 토요일 아침 스무 명의 자원봉사자가 코드를 스캔하고, 참여자 식별자로 이름을 입력하고, 연결 테스트를 통과하고, 저장합니다.

일요일 저녁 각 자원봉사자는 Session 목록을 열고, 주말의 Session을 선택하고, 공유를 누르고, 보낼 곳에서 프로젝트가 체크된 상태로 두고, **업로드**를 누릅니다. 업로드는 집의 Wi-Fi를 기다리다가 밤새 완료됩니다. 월요일에 책임자는 업로드 ID로 이름 붙은 스무 개의 폴더를 발견하는데, 각 폴더에는 ZIP이 몇 개씩 들어 있으며, 자원봉사자의 이름은 숨겨진 등록 파일이나 JSON 기록 안의 `meta.participant` 필드에서 읽습니다.

### Session 검토에서의 수정, 그리고 ARU 관측소

한 참여자가 Session을 검토하여 잘못된 감지 두 개를 제거하고, 종 하나를 직접 추가하고, 저장합니다. Session 검토 앱 바의 구름 아이콘은 이 Session이 토요일에 업로드되었음을 보여 줍니다. 참여자는 도구 모음의 공유 아이콘을 누르고, 보낼 곳에서 프로젝트를 체크하는데, 그곳에는 체크되지 않은 상태로 날짜와 함께 **업로드됨**이 표시되어 있습니다. 그리고 **업로드**를 누릅니다. 수정된 ZIP은 이전 ZIP을 대체하거나, File Drop에서는 번호가 붙은 이름으로 그 옆에 저장됩니다.

같은 참여자가 오두막에 Wi-Fi 핫스팟이 있는 갈대밭에 휴대전화를 ARU 관측소로 남겨 둡니다. 그 휴대전화에서 프로젝트 대상에 참여하고, **ARU Sessions 자동 업로드**를 켜고, **Wi-Fi에서만 업로드**를 켠 상태로 둡니다. 매일 아침 완료된 야간 주기가 대기열에 추가되고 관측소가 유휴 상태일 때 업로드됩니다. 책임자는 누구도 손대지 않아도 그 휴대전화의 업로드 ID 아래에 새 ZIP이 나타나는 것을 봅니다.

## 개인정보와 책임

업로드 대상은 BirdNET 팀이 아니라 프로젝트 운영자가 운영합니다. 폴더, 서버, 누가 읽을 수 있는지, 데이터가 얼마나 오래 보관되는지는 운영자 자신의 개인정보 및 보안 규칙에 따르므로, 참여하기 전에 운영자에게 자세한 내용을 문의하세요. BirdNET Live는 사용자가 보내기로 선택한 것만 기록하고 자격 증명을 기기의 키체인에 보관합니다.

업로드에는 공유에 담기는 것과 같은 내용이 들어갑니다: 감지, 시간, 좌표, 설정되어 있다면 관찰자 이름과 위치 이름이 담긴 Session의 JSON 기록, 기기의 업로드 ID, 사용자가 입력한 참여자 식별자, 앱 버전, 그리고 체크한 오디오, 테이블, 보고서입니다. 보내기 전에 내용 탭을 검토하고, 녹음에 목소리나 그 밖에 프로젝트에 넘기고 싶지 않은 내용이 포함될 수 있다면 오디오를 제외하세요. **업로드하는 내용에 대한 책임은 사용자에게 있습니다.** 사적이거나 기밀이라고 생각하는 데이터를 업로드하거나 공유하지 말고, 전달할 권한이 없는 녹음을 업로드하지 마세요.

## 문제 해결

| 메시지 | 의미 | 해결 방법 |
| --- | --- | --- |
| 링크나 서버 주소로 보이지 않습니다. | 텍스트가 URL이 아닙니다. | 참여 링크, 공유 링크 또는 `https://` 주소 전체를 붙여 넣습니다. |
| 서버가 자격 증명을 거부했습니다. | 비밀번호가 틀리거나 없거나, 공유가 제거되었습니다. Nextcloud는 삭제된 공유에도 이렇게 응답합니다. | 공유 비밀번호나 앱 비밀번호를 사용하고, 공유가 아직 존재하는지 책임자에게 문의합니다. |
| 이 주소는 WebDAV 엔드포인트가 아닙니다. | 공유 링크나 WebDAV 주소가 아니라 폴더의 웹 페이지를 붙여 넣었습니다. | 공유 링크(`…/s/…`) 또는 WebDAV 주소를 붙여 넣습니다. |
| 여기에는 업로드할 수 없습니다. | 공유가 읽기 전용입니다. | 책임자에게 File Drop이나 업로드 권한을 요청합니다. |
| 서버에 해당 폴더가 없습니다. | 주소가 존재하지 않는 곳을 가리키거나 폴더가 삭제되었습니다. | 책임자와 함께 주소를 확인합니다. |
| 서버 인증서를 확인할 수 없습니다. | 자체 서명 인증서이거나 TLS가 손상되었습니다. | 책임자에게 유효한 인증서가 있는 주소를 요청합니다. |
| 이 주소는 암호화되지 않은 HTTP를 사용합니다. | 로컬 네트워크 밖의 암호화되지 않은 연결입니다. | `https://` 주소를 사용합니다. |
| Wi-Fi 대기 중 | 대상이 Wi-Fi 전용으로 설정되어 있고 휴대전화가 셀룰러 네트워크에 연결되어 있습니다. | 기다리거나, 대상의 Wi-Fi 전용 스위치를 끕니다. |
| 실패, 다시 시도합니다 | 연결 끊김이나 서버 오류 같은 일시적인 문제입니다. | 할 일이 없습니다. 앱이 스스로 다시 시도합니다. **지금 다시 시도**는 즉시 시도를 강제합니다. |
| 업로드에 실패했습니다. 대상 설정을 확인합니다. | 다시 시도해도 해결되지 않는 이유로 서버가 거부했습니다. | 대상을 열어 **연결 테스트**를 실행하고, 자격 증명이 바뀌었다면 대상을 제거한 뒤 다시 추가합니다. |
| 기기 키체인에 이 대상의 자격 증명이 없습니다. | 예를 들어 새 휴대전화로 복원한 뒤 키체인 항목이 사라졌습니다. | 대상을 제거하고 다시 추가합니다. |

[업로드 대상](settings.md#업로드-대상) 설정과 [Session 목록](session-library.md) 및 [Session 검토](session-review.md) 가이드도 참고하세요.
